# CUB-200 Project Document

## Purpose

The maintenance portal is found from the available functionality and the experimental conditions, evidence and results are read back from the configuration and running records.

## Scope

For the use, maintenance and review of this classification reference item. For operational commands and installation, see [the project's first page](../README.md) (see existing functionality and normal commands from the project entry, e.g., viewing directly usable workflows).

| Level I directory | Duties and description |
| --- | --- |
| `base/cub_template/` | Commands, operational coordination and result interfaces are available [on the base level](base.md) (description of the project from configuration to distribution of components and reading of results for positioning public running responsibilities, e.g., checking how the project selects tasks). |
| `datasets/` | Data sources, samples and classifications can be found in [the data set](datasets.md) (for data selection and disaggregation, see how offline synthesis input is generated). |
| `models/` | Model series, variants and weight weights [model](models.md) (for the selection of models and weights, two ResNet18 classification head widths can be found). |
| `tasks/` | Classification, precheck and performance comparisons are shown in [Target](tasks.md) (for selection operations and access to their products, the official classification and its use for precheck). |
| `conf/` | The order of effect, the default value and the consumer are shown in [parameter](conf.md) (for the configuration file, the default value and the overriding rule, the default value and effect of `training.batch_size` can be found). |
| `experiment/` | Operating conditions, indicators, results read out [experimental report](experiment.md) (use for random initialization and fine-tuning of respective conditions based on real-time results and limitations). |
| `tests/` | Test entrances and coverage are shown in [regression inspection](tests.md) (describes the entry and coverage of the engineering inspection, which will be used to maintain the existing functionality, for example, to check which inspections cover the public entry point). |
| `.agents/` | The discovery and synchronization of shared skills [maintenance skills](agents.md) (presentation of project modus operandi and access settings to start collaborative maintenance, e.g., finding out how the assistant gets shared skills). |
