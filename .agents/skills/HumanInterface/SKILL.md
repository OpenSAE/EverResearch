# HumanInterface

## 目的和主要功能

通过交流保存值得长期使用的知识。当前提供 `note` 功能，把知识产生的情境、人类的思考、AI 的想法、使用方法、潜在作用和后续批注整理为独立的 Markdown 文件。

## 适用范围

在人类希望记录想法、沉淀交流中的知识、阅读已有记录或补充后续批注时使用。知识文件保存于本技能的 `note/` 文件夹，路径根据本技能所在位置确定，整个技能移动后仍按相对位置保存与读取。

## note：记录知识

### 从交流到保存

1. 听取人类的想法，结合当前交流理解它产生的状态或问题，提炼值得保留的核心思想。
2. 整理出标题、文件名和完整草稿。人类的思考忠实表达其原意；AI 的想法写出 AI 对这条思想的理解、推演与补充。使用方法说明怎样把知识用于实际行动，潜在作用说明它可能带来的价值。需要进一步了解的关键内容，用简短问题向人类了解；尚待补充的信息如实标为“待补充”。
3. 把拟保存的文件名和完整正文发给人类阅读。根据人类提出的修改意见调整内容，展示更新后的完整正文。
4. 人类看过后表示认可或明确没有异议，例如“可以”“很好”“就这样”“没有意见”，即视为同意保存，立即将内容保存为 `note/<两个词>.md`，返回实际文件的完整路径链接。人类认可后继续讨论其他问题时，先完成保存，再处理后续讨论。保存直接沿用这次认可。人类尚未回应时，保留已展示内容等待反馈。

初次记录的“后续批注”小节保持空白。保存后，人类提出新理解、使用反馈或补充时，读取原记录，整理并展示拟更新内容，人类表示认可或明确没有异议后即时更新对应文件。后续批注按时间顺序追加，保留思考的发展过程；正文修订采用同样的展示与即时保存规则。

### 标题与文件名

- 标题表达一条清楚的核心思想，保持在十个词以内，精简且准确。中文标题按自然语义组织为短语。
- 每条知识独立保存为 Markdown 文件，文件名由两个简短的英文单词组成，采用小写字母和一个下划线，例如 `shared_understanding.md`、`patient_reasoning.md`。文件名表达知识的实际含义。
- 保存前查看 `note/` 中已有文件。相同知识的补充归入对应记录；新的知识采用贴切且独立的两个词命名，并将文件名与正文一同展示，统一按人类的反馈保存。

### 固定记录格式

每条知识使用以下标题顺序，具体内容采用已展示并获人类认可的正文。第一行是知识标题，末尾的“后续批注”在初次保存时留空。

```markdown
# 知识标题

## 产生知识的状态或问题

描述什么情境、经历或问题催生了这条知识。

## 人类的思考

用忠实、清楚的表达整理人类的核心想法。

## AI 的想法

记录 AI 对核心思想的理解、推演与补充。

## 使用方法

说明如何在实际思考与行动中使用这条知识。

## 潜在作用

说明这条知识可能带来的帮助与价值。

## 后续批注
```

### 记录的表达方式

围绕思想本身写作，使用常见词语和完整、简明的自然语言。技术词汇按表达核心思想的实际需要使用，并用易懂的话说明含义。

采用肯定、明确的句子，直接说明思想、理由、行动与作用。事实按已有依据记载，推演按其实际含义表达，例如“我认为……”“这条知识可以帮助……”。让语言的确定性与原意、依据保持一致。

每段聚焦知识的实质，通过正面陈述表达对象与联系。全文围绕核心思想展开，保持连贯的解释；把注意力放在思想如何产生、如何理解、如何使用及如何继续发展。
