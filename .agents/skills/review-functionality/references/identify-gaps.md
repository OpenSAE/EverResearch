# 识别与补足核心功能

## 目的和主要功能

保存通过正常入口识别核心结果缺失并补足实现的操作示例。

## 适用范围

适用于判断核心功能是否完成和定位缺口时。

## 示例与预期结果

以下为简化示例。核心功能是给定特征编号，从解释库取得对应解释，并随实验结果保存。解释文本用于说明操作。

```python
解释库 = {
    31007: "影视作品与人物",
    27693: "列表与结构化格式",
}
需要的特征 = [31007, 27693]
```

预期结果：从实验结果的正式读取入口取得这两个编号及各自的解释。

## 识别步骤

| 步骤 | 具体操作 | 用来判断什么 |
| --- | --- | --- |
| 确定预期结果 | 写明最终应取得的两个编号及解释 | 核心功能要交付什么 |
| 执行当前程序 | 通过现有实验入口处理这两个特征 | 当前程序实际做到了什么 |
| 从正常入口读取结果 | 重新读取程序保存的实验结果 | 解释是否真正进入可用结果 |
| 对照预期 | 检查编号、解释及内容完整性 | 哪个必要步骤存在缺口 |

假设解释已经查到，但重新读取结果时只有编号和激活值。测试识别出的缺口就是解释没有进入正式保存与读取流程。

## 根据结果补足

定位负责保存和读取的实现，补上解释进入正式结果所需的步骤，再运行同一测试。改动直接服务于已经识别的缺口。

这项测试先帮助决定要补什么，之后继续检查补足后的结果。临时输入与调用代码按实际运行环境准备，长期保留的测试归入项目已有位置。
