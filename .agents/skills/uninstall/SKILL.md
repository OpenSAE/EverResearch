# Uninstall — 功能卸载

## 目的和主要功能

完整移除用户指定的功能及其专属依赖，让保留功能继续运行，使活动代码、接口和管理说明直接表达最终状态。

## 适用范围

用于用户要求卸载 ResearchHarness 某项功能或机制的任务。普通文件编辑、仅讨论用途或单纯调整目录时，按对应任务处理。卸载对象、实施范围和检查方式以人类讨论确定的具体需求为依据。

## 1. 查清目标及实际依赖

从目标功能的实际入口和所属管理 Markdown 开始，沿调用关系确认：

- 专属源码、导入、命令、界面、参数、默认值和配置。
- 调用它的其他功能，以及仍有用途的共享能力。
- 专属进程、自动启动项、运行状态、生成物、缓存和符号链接。
- 管理文档、技能、命令示例、测试、源码职责登记及受影响的结构成果。

区分专属内容和共享内容。混合文件、目录和配置按实际条目划分范围。已有冻结资料作为历史事实阅读，当前方案依据活动实现与当前用户决定制定。

## 2. 实施前向人类汇报具体计划

正式卸载前，先向人类展示可判断的改动计划，说明各方面影响：

| 方面 | 计划应说明的具体内容 |
| --- | --- |
| 目标与结果 | 要移除的能力、现有使用场景，以及卸载后的实际使用方式。 |
| 代码与接口 | 要删除或修改的文件、符号、命令、界面、参数和调用关系。 |
| 保留功能 | 共享实现如何归属，调用者如何改接，保留功能怎样继续运行。 |
| 配置与服务 | 要处理的配置字段、专属进程、启动项、路径及服务切换。 |
| 文件与记录 | 要清理的生成物、运行状态、临时副本、失效索引和链接；明确保留的资料。 |
| 管理说明与测试 | 要修改的 Markdown、技能、示例、源码职责和测试条目，以及本次采用的检查方式。 |
| 结构成果 | 有已保存的结构说明时，识别受影响的源码范围与对应版本。 |

取得人类对具体计划的确认后实施；同一具体计划已有确认时沿用该确认。共享文件、外部调用或资料清理范围超出计划时，先补充相关影响并确认新增范围。

项目协作沿项目的 GitHub 流程，实际文件操作采用本次授权。

## 3. 先调整保留功能，再删除目标实现

按获准计划调整保留功能的调用、数据读取和资源位置，再移除目标功能专属代码、入口和配置。

共享能力按剩余调用者继续保留或归位。例如取消独立发布步骤时，批准后更新网页仍需要一次性替换和失败恢复能力。

删除目标功能的兼容转发、空壳函数和停用提示。保留代码直接实现最终行为，活动接口使用最终名称。

## 4. 同步清理运行内容与管理说明

- 停止专属进程，处理对应自动启动项；共享服务按获准方案切换，其他进程继续保留。
- 清理专属生成物、缓存、临时工作区、备份副本及失效链接，具体对象以计划为准。
- 同步处理依赖已清理产物的状态、索引和工作区日志条目。
- 修改实际受影响的管理 Markdown、技能、示例、测试和源码职责登记，使其与最终实现一致。
- 保留功能继续使用适用的身份、文件范围及具体操作授权检查。

活动代码和文档只描述最终功能，清除“已经卸载”“已退役”等过程说明。新增归档、备份、迁移说明或删除日志时，以用户明确要求的内容与范围为依据。既有冻结档案和无关资料保持原样。

## 5. 按确定的方式检查最终状态

查找活动入口、导入、配置、文档和符号链接中的悬空依赖，检查专属进程和产物是否按计划处理。

按本次确定的检查方式确认保留功能能够独立使用。测试保留有实际意义的行为检查，并随最终接口调整；中央程序测试使用 `tests/`，运行产物使用 `.workspace/tmp/tests/`。优先使用明确标记的合成输入，真实操作按其具体授权执行。

检查资料记录各场景实际确认的行为与依据；发现影响保留功能的问题时继续修复。

## 6. 按实际影响维护结构成果

项目已有结构说明时，按其源码版本读取历史内容。用户要求反映新结构时，用 ExtractStructure 按实际变动范围生成新成果，再用项目结构入口登记。每份审阅决定关联到提交审阅的具体页面版本。

## 7. 保存执行记录并交付

清理已完成用途的临时脚本、合成工作区及临时副本；保留能解释本次处理的简短任务记录和仍有用途的产物。任务记录按时间说明卸载原因、重要调整、实际效果和后续建议，链接已有资料。

交付移除后的实际使用方式和共享功能的必要调整。当前任务涉及结构成果时提供相应页面；遇到影响完成的问题，持续处理并给出已知原因与可行方案。
