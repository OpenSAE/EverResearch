# 维护科研项目基础层

## 目的和主要功能

让项目入口依据生效配置接好数据、模型和科研任务，并让共用的运行能力有明确负责位置。基础层优先位于项目根目录的 `base/`，已有清晰的运行包也可承担同等职责。

## 适用范围

用于接入或调整项目级运行流程，包括参数合成、按标识选择组件、交付任务所需对象、调度任务、生命周期管理、通用检查点或运行记录。组件自己的数据语义、模型构建和科研计算由其实现维护。通过项目 README、配置和实际调用点确定本次范围。

从项目 `AGENTS.md`、README 或接入说明找到实际命令。沿命令追到配置来源、基础层、组件实现、任务入口和结果读取者。采用 ResearchHarness 布局的项目优先在根目录 `base/` 定位协调实现，已有项目也可从 `<主包>/runtime/` 等实际等价入口进入。

- **增加。** 接通新的项目级入口、组件组合或已有多个调用者需要的运行能力。
- **修改。** 调整配置解析、组件分发、运行资源管理或共用结果读写，沿实际调用同步受影响的位置。
- **移除。** 移除指定分发选项、运行支持或结果接口，先处理仍在用它的入口和历史结果读取者。

[基础层操作方案](references/procedures.md)说明基础层各路径由谁调用、什么情况下启用，以及新增、修改和移除时的实施顺序与完成条件。
