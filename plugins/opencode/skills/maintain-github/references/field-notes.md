# GitHub 维护经验

## 目的和主要功能

记录实际维护中遇到的问题、定位方法和验收证据。遇到类似情况时，按对应条目复查。

## 适用范围

用于 GitHub 仓库更新、研究模板迁移、插件同步和正式发布。发布范围与审批流程按主技能执行。每条经验记录触发条件、处理步骤和完成证据。

## Git LFS 和模板迁移

### 含指针的模板克隆失败

- **实际现象。** GitHub 可以浏览已提交的文件路径，启用 Git LFS 的新克隆却在下载测试图片、视频或权重文件时收到 404。普通 Git 提交保存的是包含 SHA-256 和文件大小的指针，真实内容由 Git LFS 单独存储。
- **逐项定位。** 从目标提交枚举指针，按路径、SHA-256 和大小建立清单，再核对目标仓库的实际下载结果。迁移模板时，目录经常重新组织。用原始提交的归档或 Git 树按 SHA-256 找回上游路径，再从固定提交下载对象。EverResearch 的 LeRobot 模板把上游的 `tests/artifacts/` 整理到了 `tests/fixtures/artifacts/`。
- **补传对象。** 下载后逐个比对 SHA-256 和大小。将缺失对象放入隔离 Git 副本的 LFS 对象库，使用有目标仓库写权限的身份执行 `git lfs push --object-id`。原样保留指针和属性规则。
- **验收。** 从目标 GitHub 仓库进行一次启用 LFS 的全新普通克隆，读取实际文件，逐项复核大小和 SHA-256，并运行 `git lfs fsck --objects HEAD`。扫一遍其余模板的已跟踪路径，记录还有哪些指针和哪些下载失败。

### 插件安装连带读取研究模板

- **实际现象。** Codex 添加 GitHub 市场时会克隆仓库，模板里的 LFS 对象缺失会中止插件安装。
- **处理。** 让支持稀疏检出的宿主只取市场清单和目标插件目录。对必须完整检出的 Skills CLI，安装步骤可跳过与插件无关的 LFS 下载。模板则继续单独验证真实对象完整性。
- **验收。** 使用空插件缓存从公开仓库安装，再运行插件入口。完整模板克隆和插件安装各保存一份验证记录。

## GitHub 更新范围和审批

### 新模板已做完，远端却少了一批

- **实际现象。** 按最近讨论的文档手工选文件，发布副本会漏掉同一项目的其他变更。EverResearch 曾出现本地 20 个模板、远端 9 个的差距。
- **处理。** 从根目录枚举所有未忽略的变更，以最近一次实际远端更新为基线。用户明确限定范围时按该范围。对照实际目标分支和待提交的文件清单，确认新目录、配套文件和原有 PR 内容都纳入对应审阅。
- **验收。** 回查目标提交的文件树，比较模板或技能数，同时核对具体路径和内容。更新主分支前展示实际差异并取得相应批准。

## 正式发布、回退与验证

### GitHub 源码、插件技能和公开发行进度不同

- **准备。** 先记录当前公开版本和目标源码提交，按本次授权选择日常更新或正式发版。核对包版本、引用文件、变更日志、中英文安装链接、插件清单和自动发布工作流。
- **正式发布顺序。** 取得对指定版本和渠道的批准，基于同一确认提交构建并校验。先发布安装文件，再更新指向它们的市场和安装入口。按批准范围同步下游项目。逐个渠道做匿名下载和空环境重装，核对实际运行版本。
- **日常更新。** 仓库里的插件技能可以从源技能同步。保持已发行的版本和运行时校验值，对需要当前源码运行时的技能写明适用入口。确认推进主分支只触发预期的检查。
- **撤回后复查。** 分别检查 GitHub Release、标签、包仓库和插件索引的公开状态，再对齐本地与远端的版本字段、安装链接和变更日志。源码分支恢复后，从公开入口重装一次，确认默认安装实际选择了预期版本。
