# Design discussion on core functional review skills

## Purpose

Core purpose of record-keeping skills, issues raised by humans and established principles of judgement.

## Scope

This applies to the continued discussion, revision and testing of this skills.

## Core objectives have been identified

Systematically read, cross-reference and modify existing codes to make them more direct and fully implement their core functions.

Understanding the function and upstream/downstream relationship of the document, through testing around core uses, identifies and addresses two types of issues:

- Excessive: non-functional functions, duplicates, defence and border checks away from core uses.
- Missing content: what is really needed to complete the core function, is not being achieved at this time or is not being correctly achieved.

The skills themselves must be streamlined and implementable. A simple, stable basis for a broadly reliable judgement is used to reduce the free exercise of smart assistants and to avoid complex analysis, additional checks and manual decision-making for each document reviewed.

## Human design questions.

1. How do you determine the core function of a document? Can you do this using an extract-structure?
2. How to judge that the core functions of a document have been completed? What principles are the tests designed for this purpose, what tests should be performed and what tests can be saved?
3. How to screen the irrelevant functions of a document? What principles are the tests designed for this purpose, what tests should be performed and what tests can be saved?
4. How can core functions be supplemented or irrelevant functions deleted?
5. How can cross-documentation and consolidation of functions be considered on this basis?
6. How can the above-mentioned reading, routing, testing and modification process be kept light and the implementation process itself reduce the additional work burden?

## Key requirements under discussion

The functional trade-offs revolve around the actual purpose. Each fact is determined by a clear location, followed by a call for the reuse result.

The results should support concrete action. Smart assistants, within their mandates, are proactive in investigating and dealing with matters that truly require human judgment.

The assistant undertakes the code fact-finding, achieves sufficiency judgement and optimizes the work that has been authorized. Humans primarily provide research intent, actual use feedback and input preferences, determining functional value, scientific implications, and important trade-offs.

The collaboration begins with an understanding of the results that the user wishes to obtain and continues to be pursued as long as the information is available. When larger adjustments involving functional value or use are made, the results are presented as early as possible, using a representative case, comparison or use process, and the orientation is based on feedback.

The report begins with a description of the conclusions, changes and uses, the background and details of which are organized according to user awareness and current decisions. Four parts of the complete report are presented as options for complex subjects, maintaining the existing background and judgement on a continuous basis.

The rules should be generally in place at the time of implementation of the different smart assistants.

## The availability of anextra-stucture

Read an overview of the engineering catalogue, the internal structure of the document and the expression of the actual collaborative relationship. The explanation in the diagram is organized by the smart assistant based on the source code and document, the diagram itself provides understanding and navigation, and the completion is a description of the actual behaviour of the function.

The first draft contains the required reading methods and does not operate on the self-defined basis of other skills directories.

## Simplified orientation of the first draft

In a sentence, summarize the tasks, inputs and results of the document service; understand its responsibilities in the context of actual realization and direct callers.

Priority is given to mechanisms that address clear functional gaps, duplicate realizations and end-uses.

The document is used to schedule reading, functions and their call relationships for organizational changes.

## Established principles for determination

Use the normal use of the scene to define the results required. The absence of a particular step leads to the non-availability of the result, which is completed; and the removal of a step that still has the required results will streamline the process.

The test is an experiment used to make a change decision.

The same set of portable core function tests is used to identify gaps, to decode candidates and to judge the results of the migration merger.

Test-description scenarios use the assurance and known failure conditions on which the current caller relies.

## Principle and operational division of labour

Skills principles preserve the basis for functional trade-offs.

The design principles are discussed around the basis of judgement and the cost of implementation.
